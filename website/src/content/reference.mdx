# React hooks

Choose a hook based on how the value will be used:

- [`useObservable`](#useobservable) reads values for results, previews, and other content that can
  update in the background.
- [`useSyncObservable`](#usesyncobservable) reads values for controlled inputs, where each edit must
  be reflected synchronously.
- [`useObservablePromise`](#useobservablepromise) lets a child wait for the first value with
  React's `use()` and Suspense.
- [`useObservableSubject`](#useobservablesubject) gives event handlers a way to send values into an
  observable pipeline.

For ordinary local state without an observable, React's `useState` is enough. The
[guide](/guide) shows how these hooks fit together; the
[full app demo](https://async-react.sanity.dev/) puts the async patterns in a larger application.

## useObservable()

Returns the latest value from an observable. Updates are deferred with React's
[`useDeferredValue`](https://react.dev/reference/react/useDeferredValue): urgent renders keep the
previous value while React prepares the next one in the background. If a child suspends on that
update, already-visible content can stay on screen instead of being replaced by a fallback.

Use this for search results, previews, validation messages, and lists. A controlled input's `value`
needs [`useSyncObservable`](#usesyncobservable) instead.

**Initial values and subscriptions**

`initialValue` is required, even if the observable emits synchronously. The hook does not subscribe
during render: it first renders the initial value, then subscribes when the component commits.
If another consumer has already received a value from the same observable, the hook can read that
shared value instead.

Every value is valid as an initial value, including an explicit `undefined`. Omitting the argument
throws during render. Functions are lazy initializers, as with `useState`: use `() => value` to
compute a value, or `() => myFunction` when the value itself is a function. The hook keeps the
resolved initial value for its lifetime; changing the argument does not reset it. If there is no
useful initial value, consider [`useObservablePromise`](#useobservablepromise).

**Keeping the observable stable**

Reuse the same observable instance while its inputs are unchanged. Create it at module scope,
with `useMemo`, or with a `useState` initializer; React Compiler memoization can also keep it
stable. Creating a new observable on every render causes repeated subscriptions. If that
observable synchronously emits a value different from `initialValue`, this can cause a render loop.

When you intentionally switch observables, the hook reads the new observable's latest shared
value, or the resolved initial value if it has not emitted. It does not return the previous
observable's deferred value under the new identity.

Mounts, remounts, and `<Activity>` reveals read the current snapshot without deferring it. A
retained snapshot is shown directly rather than briefly returning to the initial value. On the
server, no subscription starts and the hook renders the resolved initial value.

**Signature**

```ts
function useObservable<T>(
  observable$: Observable<T>,
  initialValue: T | (() => T),
  options?: UseObservableOptions,
): T
function useObservable<T, InitialValue>(
  observable$: Observable<T>,
  initialValue: InitialValue | (() => InitialValue),
  options?: UseObservableOptions,
): T | InitialValue

interface UseObservableOptions {
  disabled?: boolean
}
```

`disabled` defaults to `false`. When `true`, this hook does not subscribe or receive notifications
for later emissions. It keeps the last value, or the initial value if nothing has arrived.
Other consumers of the same observable can still be subscribed; disabling one hook does not stop
them. See the [guide](/guide) for subscription sharing.

Observable errors are thrown during rendering so an Error Boundary can handle them. Use RxJS
`catchError` in the pipeline if an error should become a value in the UI instead. Completion leaves
the last value in place; completing without an emission leaves the initial value.

**Example**

```tsx
import {useMemo} from 'react'
import {useObservable} from 'react-rx'
import {interval} from 'rxjs'

function MyComponent() {
  const observable = useMemo(() => interval(100), [])
  const number = useObservable(observable, 0)

  return <>The number is {number}</>
}
```

## useSyncObservable()

Returns the latest value from an observable synchronously, using
[`useSyncExternalStore`](https://react.dev/reference/react/useSyncExternalStore).

Choose this when the value feeds a controlled input or needs to stay consistent within the same
event. A search field can use this hook for its text and [`useObservable`](#useobservable) for its
results.

“Synchronous” describes how updates reach React, not when subscription begins. As with
`useObservable`, the hook never subscribes during render, including when the observable changes.
It reads the initial value or an existing shared value, then subscribes at commit. Keep the
observable instance stable between renders.

`initialValue` is required and follows the same rules as [`useObservable`](#useobservable), including
lazy initialization and explicit `undefined`. Omitting it throws during render. The server always
renders the resolved initial value. The `disabled` option, error handling, and completion behavior
also match `useObservable`.

Store mutations cannot be marked as Transitions. If a child suspends on a value returned by this
hook, React replaces already-visible content with the nearest Suspense fallback. Use
`useObservable` for reads where that would interrupt the user. The
[side-by-side example](/examples/suspense) demonstrates the difference; React explains it in the
[`useSyncExternalStore` caveats](https://react.dev/reference/react/useSyncExternalStore#caveats).

**Signature**

```ts
function useSyncObservable<T>(
  observable$: Observable<T>,
  initialValue: T | (() => T),
  options?: UseObservableOptions,
): T
function useSyncObservable<T, InitialValue>(
  observable$: Observable<T>,
  initialValue: InitialValue | (() => InitialValue),
  options?: UseObservableOptions,
): T | InitialValue
```

**Example**

```tsx
import type {ChangeEvent} from 'react'
import {useMemo} from 'react'
import {useObservableSubject, useSyncObservable} from 'react-rx'
import {map} from 'rxjs'

function SearchField() {
  const [changes$, handleChange] = useObservableSubject<ChangeEvent<HTMLInputElement>>()
  const text$ = useMemo(() => changes$.pipe(map((event) => event.currentTarget.value)), [changes$])
  // Controlled input values must update synchronously.
  const text = useSyncObservable(text$, '')

  return <input value={text} onChange={handleChange} />
}
```

## useObservablePromise()

Returns a promise that a child can read with React's
[`use()`](https://react.dev/reference/react/use). Choose this when the first value should reveal
content through Suspense rather than replace an initial value you provide. For a field or preview
that already has a useful starting value, use one of the value-reading hooks above.

**Signature**

```ts
function useObservablePromise<T>(
  observable: Observable<T>,
  options?: UseObservablePromiseOptions,
): ObservablePromise<T>

interface UseObservablePromiseOptions {
  disabled?: boolean
  ttl?: number
}

type ObservablePromise<T> = Promise<T> &
  ({status: 'pending'} | {status: 'fulfilled'; value: T} | {status: 'rejected'; reason: unknown})
```

**Place Suspense below the hook caller**

The hook itself does not suspend. Pass its promise to a child that calls `use(promise)`, with a
`<Suspense>` boundary **between the hook caller and that child**. The caller can then commit while
the child waits, and that commit starts the subscription.

Do not call `use()` on the returned promise in the same component as the hook, or let a child's
suspension reach the hook caller without a boundary between them. On a fresh mount, the caller
would wait for data before committing, but the data cannot start until it commits. The hook does
not detect or guard against this deadlock.

**First values, later values, and errors**

The first emission fulfills the pending promise. Later changed values produce already-fulfilled
promises, so `use()` reads those updates without suspending again. Values equal by `Object.is`
reuse the current promise. An RxJS `startWith` value counts as the first emission: a loading
placeholder in the stream will fulfill the promise rather than keep the fallback visible.

An observable error makes the hook return a rejected promise, and `use()` passes the error to an
Error Boundary.
Completion without any emission rejects with RxJS `EmptyError`. Completion after a value keeps
that value available. A source that neither emits nor completes stays pending.

**Subscription timing and changing sources**

Keep observable instances stable: the cache uses the observable itself as its key, not a URL or
other request argument. Consumers using the same instance can share the pending promise and
subscription.

A fresh mount does not subscribe during render. There are three ways a subscription can start:

- The hook caller commits.
- [`preloadObservablePromise`](#preloadobservablepromise) starts it before a consumer mounts.
- An already-committed, visible, enabled consumer renders a new observable. In this case the hook
  starts the new source during that render so a suspended transition can finish.

That last case is an exception to commit-time subscription. It lets you change the source inside
`startTransition` or behind `useDeferredValue` while keeping previous content visible. Mounts,
server renders, disabled consumers, and hidden `<Activity>` pre-renders do not use this exception.
An abandoned transition may therefore leave a request running without a consumer. Use RxJS
`timeout` or source cancellation for work that might never settle; `ttl` does not time out pending
work. Try the [transitions example](/examples/transitions).

**Options**

- `disabled` defaults to `false`. When `true`, this component neither starts a subscription nor
  receives notifications for later emissions. The returned promise still comes from the shared
  cache: another consumer or a preload can fulfill it. Otherwise it stays pending until the hook
  is enabled. Later promise changes are read when the disabled component renders for another
  reason.
- `ttl` defaults to `500` milliseconds, also exported as `DEFAULT_HOOK_TTL`. Once the entry has
  settled and has no live subscribers, it controls how long the cached result and shared
  connection are retained. An entry uses the largest `ttl` requested by its consumers. This is
  retention, not a request timeout or a refetch interval. Eviction affects future consumers;
  mounted components retain their entry, including when hidden or disabled.

**Activity and server rendering**

A hook inside a hidden `<Activity>` tree stays paused until reveal. To load data for hidden
content, call the hook in a visible parent and pass the promise into the hidden tree. The
[Activity example](/examples/activity) compares this with preloading on hover.

These are client-component APIs. On the server, the observable is not subscribed, so the promise
stays pending and Suspense renders its fallback. Fetching starts after hydration when the caller
commits. For React Server Components or server-only data flows, fetch on the server rather than
using this hook. See the [guide](/guide).

**Example**

```tsx
import {Suspense, use, useMemo} from 'react'
import {useObservablePromise} from 'react-rx'
import {fromFetch} from 'rxjs/fetch'

function Profile({url}: {url: string}) {
  const data$ = useMemo(() => fromFetch(url, {selector: (r) => r.json()}), [url])
  const promise = useObservablePromise(data$)
  return (
    <Suspense fallback="Loading…">
      <Pre promise={promise} />
    </Suspense>
  )
}

function Pre({promise}: {promise: Promise<unknown>}) {
  return <pre>{JSON.stringify(use(promise), null, 2)}</pre>
}
```

## preloadObservablePromise()

Starts an observable before a component needs its value and returns the promise from the
[`useObservablePromise`](#useobservablepromise) cache. It is not a hook. Call it outside rendering,
for example in a hover handler or a client-side route loader, and pass the **same observable
instance** to the hook later.

A preload starts the subscription immediately if needed and renews the retention window for an
existing entry. It returns the same current promise the hook would read. Transition swaps from a
live consumer do not require preloading, but starting on hover can shorten the wait after a click.

**Signature**

```ts
function preloadObservablePromise<T>(
  observable: Observable<T>,
  options?: PreloadObservablePromiseOptions,
): ObservablePromise<T>

interface PreloadObservablePromiseOptions {
  ttl?: number
}
```

`ttl` defaults to `5000` milliseconds, also exported as `DEFAULT_PRELOAD_TTL`. It follows the
hook's retention rules, with a longer default to allow time between hover and click.

Pending entries are not timed out. A source that never emits or completes can keep the promise and
subscription alive indefinitely. Use RxJS [`timeout`](https://rxjs.dev/api/operators/timeout) or
cancel the source when that is possible. Errors, including `EmptyError` on empty completion, follow
the same rules as `useObservablePromise`.

On the server, this function does not subscribe or use the cache. It returns a promise that stays
pending, so a preload in shared server/client code only does useful work in the browser. See
[Activity and preload](/examples/activity) for a runnable example.

## useObservableSubject()

Creates an event stream for one component instance. It returns an observable and a handler that
sends values into it. Both keep the same identity across renders.

Use this when React events need RxJS operators such as `scan`, `switchMap`, or `concatMap`. If the
handler only sets a local value, `useState` may be simpler. The underlying `Subject` is not exposed:
send values through the handler and compose the observable with `pipe`. You can pass the handler
to an event prop or memoized child without adding `useCallback`.

This hook does not subscribe or keep the latest event. Values sent while nothing is subscribed
are dropped. Read a derived stream with [`useObservable`](#useobservable) or
[`useSyncObservable`](#usesyncobservable) when it produces UI. For work that does not render a
value, subscribe in an effect and clean up on unmount.

This replaces `useObservableEvent`, which was removed in v7. See the
[migration guide](/migrate/v6-to-v7#useobservableevent-is-removed).

**Signature**

```ts
function useObservableSubject<T>(): [events$: Observable<T>, handleEvent: (event: T) => void]
```

**Example**

```tsx
import {useMemo} from 'react'
import {useObservableSubject, useSyncObservable} from 'react-rx'
import {map} from 'rxjs'

const ShowSliderValue = () => {
  const [input$, handleChange] = useObservableSubject<string>()
  const value$ = useMemo(() => input$.pipe(map((value) => Number(value))), [input$])
  // The derived stream is the state — no setState mirror needed.
  const value = useSyncObservable(value$, 1)

  return (
    <>
      <input
        type="range"
        value={value}
        onChange={(event) => handleChange(event.currentTarget.value)}
        min={1}
        max={10}
      />
      <div>Value is: {value}</div>
    </>
  )
}
```

For work such as saving a search, subscribe in an effect instead. This example assumes
`saveSearch` is your application's function returning an observable or promise. `concatMap` waits
for one save to finish before starting the next:

```tsx
import {useEffect} from 'react'
import {useObservableSubject} from 'react-rx'
import {concatMap} from 'rxjs'

function SaveSearchButton({term}: {term: string}) {
  const [saves$, handleSave] = useObservableSubject<string>()

  useEffect(() => {
    const subscription = saves$.pipe(concatMap((t) => saveSearch(t))).subscribe()
    return () => subscription.unsubscribe()
  }, [saves$])

  return <button onClick={() => handleSave(term)}>Save search</button>
}
```

## What happened to useObservableEvent()?

It was removed in v7. Use [`useObservableSubject`](#useobservablesubject) and read the derived stream with one of the other hooks — see [Handling events](/guide#handling-events) and the [v6 → v7 migration guide](/migrate/v6-to-v7#useobservableevent-is-removed).
