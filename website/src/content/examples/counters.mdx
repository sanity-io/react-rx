# Controlled state

React controlled inputs need their value available synchronously on every keystroke. That is the one
place to reach for [`useSyncObservable`](/reference#usesyncobservable) instead of the deferred
[`useObservable`](/reference#useobservable).

<BasicState />

This form keeps two text fields and a checkbox in a single stream:

- [`useObservableSubject`](/reference#useobservablesubject) gives one stable `handleChange` for every
  input; its identity never changes between renders.
- `scan` folds each `{field, value}` change into one `FormState` object — a single source of truth,
  like a tiny reducer.
- `useSyncObservable` reads that state synchronously, so typing never drops or lags a character.

The greeting combines two variables, `first` and `last`, plus the checkbox — all derived from the
same state value.

**Try this:** add a third field. Extend `FormState` and `FormChange` with `city`, add one more
`<input>`, and read `state.city`. The subject, the `scan`, and the hook need no other changes.

**Try this:** swap `useSyncObservable` for `useObservable`. Updates become deferred, and fast typing
can momentarily show a stale value in the input — the reason controlled inputs use the synchronous
hook.
