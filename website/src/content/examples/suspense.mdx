# Suspense & deferred values

The same search text can update an input immediately and update results in the background.
This example shows why those reads need different hooks when rendering results can suspend.

Type a word, wait for results, then add another letter. Compare the two panels:

- **Left (`useSyncObservable`)**: when the next results suspend, React shows the loading fallback
  in place of the previous results.
- **Right (`useObservable`)**: previous results stay visible and are dimmed until the next results
  are ready.
- **The input** uses `useSyncObservable` so its controlled value updates synchronously.

## Why this happens

[`useSyncExternalStore`](https://react.dev/reference/react/useSyncExternalStore#caveats) cannot
mark store mutations as Transitions. `useObservable` uses
[`useDeferredValue`](https://react.dev/reference/react/useDeferredValue) to let an update wait in
the background when a child suspends. A second, synchronous read in the right panel lets it compare
the displayed keyword with the current one and dim stale results.

The simulated search caches promises by keyword. Returning to a keyword that already loaded may
not suspend, so try new text when comparing the panels. These previews run on the client; they do
not demonstrate server rendering or hydration.
