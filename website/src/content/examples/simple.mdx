# Clicks become streams

A click is an event. A sequence of clicks is a stream. This lesson follows the
[RxJS overview](https://rxjs.dev/guide/overview): count events, control how often they get through,
then transform their values. Here, the starting point is React with RxJS rather than plain JavaScript.

Try both counters, then open `ManualCounter.tsx` and `ReactRxCounter.tsx` to compare their source.
Each is a complete component you can copy into a project.

## Manual wiring vs. the hook

The first two buttons keep independent counts but perform the same calculation:

- **React + RxJS** creates a stable `Subject`, subscribes in an effect, copies each count into
  `useState`, and unsubscribes on cleanup. It does not import react-rx.
- **With react-rx**, `useObservableSubject` supplies the event stream and handler.
  `useObservable` reads the count and owns the subscription. The `scan` calculation is unchanged.

`scan((total) => total + 1, 0)` is the running count: RxJS's version of `reduce` that emits a new
total on every step.

**Try this:** change `total + 1` to `total + 2` in either counter. You are changing the stream's
calculation, not how the component subscribes. `useMemo` keeps the react-rx pipeline stable between
renders; creating it inline would restart its subscription.

## Flow control

The third section's **Click quickly** button feeds two displays. The first pipes clicks through
`throttleTime(1000)` before counting. It accepts the first click immediately, then ignores clicks for
one second. Ignored clicks are not queued for later.

**Try this:** change `throttleTime(1000)` to `throttleTime(250)` and click quickly. More clicks get
through now, because flow control lives in the pipeline, not in the component.

## Value transformations

The parity display counts every click, without throttling, and maps the count to `even` or `odd`.
It can change while the throttled count stays still. Different pipelines can describe different
uses of the same event stream.

**Try this:** add `throttleTime(1000)` before `scan` in `Parity`. Both displays now count only accepted
clicks. The order of the operators determines what “a click” means to each result.

For a counter on its own, `useState` is simpler. The benefit here is that counting, timing, and
transformations compose in RxJS without adding effects or timers to the component.
