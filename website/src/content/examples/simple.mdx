# Read your first observable

A button's clicks are a stream of events over time — exactly what an observable models. This lesson
counts the same clicks four ways, so you can see what [`useObservable`](/reference#useobservable)
replaces and what RxJS adds on top.

<Simple />

## Manual wiring vs. the hook

The first two rows always agree, because they count the same stream:

- **Manual useEffect** subscribes in an effect, copies each value into `useState`, and unsubscribes
  on cleanup. This is the integration boilerplate react-rx exists to remove.
- **react-rx useObservable** reads the `scan` stream directly — no effect, no setter, no cleanup to
  forget.

`scan((total) => total + 1, 0)` is the running count: RxJS's version of `reduce` that emits a new
total on every step.

**Try this:** delete the `ManualCount` component and its usage in the editor. The react-rx row keeps
working with a fraction of the code.

## Flow control

The throttled row pipes the same clicks through `throttleTime(1000)` before counting, so it rises by
at most one per second no matter how fast you click.

**Try this:** change `throttleTime(1000)` to `throttleTime(250)` and click quickly. More clicks get
through now, because flow control lives in the pipeline, not in the component.

## Value transformations

The last row maps the count to a label with `map((total) => (total % 2 === 0 ? 'even' : 'odd'))`.
RxJS turns the raw count into something ready to render, and the hook just reads the result.

Each number is the value the hook currently holds — a real count of emissions, not a tally of
renders.
