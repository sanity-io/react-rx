# Transitions and refetching

Once a profile is visible, selecting another should not have to replace it with a loading message.
This example uses React's
[client-side refetch pattern](https://react.dev/reference/react/use#re-fetching-data-in-client-components):
change the observable inside `startTransition` and keep the previous profile visible while the
next one loads.

Try it:

1. Wait for Ada to load, then click **Grace**. Ada stays visible while the pending timer runs for
   about 1.5 seconds.
2. Click **Ada** again within a minute. With `ttl: 60_000`, the settled result is still cached, so
   this switch does not need another wait.
3. Click **Reset demo**. This creates fresh observables and remounts the switcher. The initial
   request starts at commit and shows the Suspense fallback.

The requests here are simulated with timers. The same subscription rules apply to an observable
that performs a network request.

Normally, [`useObservablePromise`](/reference#useobservablepromise) starts its subscription when
the caller commits. There is one important exception: an already-committed, visible, enabled
consumer can start a newly selected observable during render. Without that exception, a suspended
transition could wait for data whose subscription cannot start until it commits.

This also works when the selected source is behind `useDeferredValue`. Fresh mounts, server
renders, disabled consumers, and hidden `<Activity>` pre-renders do not start subscriptions
during render.

## The rules that still apply

- **Reuse observable instances.** The `Map` in `fetchProfile$` gives each profile one instance.
  Creating a new observable on every render would create a different cache entry each time.
- **Keep the boundary between parent and child.** The hook caller passes the promise to a child
  that calls `use()`, with Suspense between them. Calling `use()` on the hook's own pending promise
  in the same component prevents the initial mount from committing and starting its subscription.
- **Preloading is optional for a live swap.** Starting a request on hover can shorten the wait,
  but this example does not need it to complete a transition.
- **Abandoned transitions may leave work running.** A request started during a transition can
  outlive that transition. Once settled, an unused entry expires after `ttl`. Pending work is not
  timed out by the cache; use RxJS [`timeout`](https://rxjs.dev/api/index/function/timeout) or
  source cancellation if it might never settle.
